This page answers the five questions of your application with my own work: a watershed study I did in ArcGIS, and the tool I built afterwards to solve the data problem I ran into while doing it.

1 · GIS experience

ArcGIS for watershed analysis, Python for spatial processing

What GIS tools have you used, and what types of projects have you worked on?

I have used ArcGIS, mainly the Spatial Analyst hydrology tools, for watershed analysis. For the Sucre watershed I produced:

  • A slope classification map
  • A shaded relief (hillshade) map
  • Contour lines
  • The drainage network
  • A map of the precipitation stations, with a color gradient showing how far each station's rainfall is from the basin's mean

To make that last map I had to download rainfall records from IDEAM, Colombia's national hydrology and weather institute, one station at a time. It took hours, so I built my own tool to do it. That tool is my main project and the subject of the next answers. I built it in Python with GeoPandas and Shapely for the spatial work, and it runs as a web app that also works on a phone.

2 · Spatial analysis

Selecting stations by area, buffer and data coverage

Can you describe a project where you combined geographic data layers, used buffers or drive-time analysis, or filtered locations based on specific criteria?

In the IDEAM Downloader, the user defines a study area and the app returns the stations worth using inside it. These are the steps, and what each one solved:

  • Study area. Drawn on the map, or uploaded as a Shapefile, GeoJSON, KML or GeoPackage. Many real files arrived with self-intersecting polygons or no coordinate system, so the app repairs the geometry and refuses files whose coordinates it cannot place, instead of guessing.
  • Buffer. Stations just outside a watershed are often still useful, so the user can add a buffer. I compute it in a metric projection for Colombia (MAGNA-SIRGAS, EPSG:3116) so that 2 km really means 2 km.
  • Spatial join. A point-in-polygon join between the national station catalog and the area plus buffer. Users can also select stations by department, municipality and station code, like in the official portal.
  • Filter by criteria. Each station gets an estimate of how much of the requested period its records cover, classified as high (70% or more), medium, low or critical. The map can be filtered by that range before downloading.
  • Cross-check. I found stations whose altitude in the catalog did not match the terrain. The app now compares each one against an elevation model and flags the ones that disagree, so they are reviewed instead of trusted.

I have not done drive-time analysis yet. For truck-stop screening I would follow the same pattern: buffers or drive-time areas around interchanges, a join with competitors, traffic and parcels, and flags for anything that needs a closer look.

3 · Data research

Combining public sources that were not made to work together

Have you collected or consolidated data from multiple websites, public databases, or other sources? What tools or methods did you use?

The downloader combines these sources:

SourceWhat I use it for
IDEAM DHIME portalTime series of every station: precipitation, temperature, river levels and other variables
IDEAM national station catalogLocation, altitude, municipality and status of each station
Terrain model (SRTM-based elevation tiles)Checking station altitudes and drawing the 3D relief
Esri satellite and relief, OpenStreetMap, NASA night imageryBasemaps to locate the study area
User files (Shapefile, GeoJSON, KML, GeoPackage)The study area itself

The DHIME portal has no public documentation for its data service, so I studied how the portal requests the data and automated it in Python. Long periods are split into blocks of years, the spreadsheets that come back are merged into one file per station, and the app limits itself to four downloads at a time so it does not overload the public server.

4 · Decision-ready deliverables

A package that shows which data is worth using

Can you share an example of a map, spreadsheet, dashboard, or report you created to support a business decision? What was your personal contribution?

The decision the downloader supports is which stations to use in a study, before spending time on them. The map shows each station colored by data coverage, and the final download is one ZIP with:

  • One Excel file per station, already merged, in IDEAM's original format
  • A summary table with one row per station and its coverage
  • Optional folders by coverage class, so the best data is easy to find
  • A citation file with the source in the format IDEAM requires

Before downloading, the app also estimates the size and time of the download. I checked that estimate against real downloads and it stays within a few percent.

My contribution: the whole project is mine. I designed it, wrote the code, built the interface and wrote the user manual. The Sucre watershed maps are also my own work.

Individual project. Its public release is pending authorization from IDEAM, and it is not an official IDEAM product. The station data belongs to IDEAM and is cited in every download.
